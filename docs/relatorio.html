Otimização da Distância de Levenshtein: análise de pior caso, provas e demonstração empírica

Resumo

A distância de Levenshtein mede o número mínimo de inserções, deleções e substituições de caracteres necessárias para transformar uma palavra em outra. É a base de corretores ortográficos e de sistemas de busca aproximada (fuzzy search). Este trabalho analisa três algoritmos para o problema: a recursão ingênua, o algoritmo de Wagner-Fischer (programação dinâmica) e a variante de Ukkonen com faixa diagonal limitada por um limiar de erros kk. Para cada um, provamos formalmente o custo de pior caso e o confirmamos empiricamente contando operações numa implementação em TypeScript. Os resultados são: a recursão ingênua é exponencial, com Ω(4n/n)≤T(n)≤O(9n)\Omega(4^n/n) \le T(n) \le O(9^n) e, de forma exata, T(n)=Θ((3+22)n/n)T(n) = \Theta\big((3+2\sqrt2)^n/\sqrt n\big); Wagner-Fischer é Θ(m⋅n)\Theta(m\cdot n) em tempo, com espaço reduzível de Θ(m⋅n)\Theta(m\cdot n) para Θ(min(m,n))\Theta(\min(m,n)); e Ukkonen é Θ(k⋅min(m,n))\Theta(k\cdot\min(m,n)) no pior caso e Ω(1)\Omega(1) no melhor. Uma aplicação web interativa (Next.js + React) acompanha o trabalho e permite reproduzir cada resultado.

Palavras-chave: distância de edição; programação dinâmica; análise assintótica; pior caso; busca aproximada.

1. Introdução

Quando um usuário digita “algorimto”, o sistema precisa encontrar “algoritmo” entre milhares de palavras de um dicionário em poucos milissegundos. O critério de semelhança mais usado é a distância de edição de Levenshtein [1]. Como a função é avaliada milhares de vezes por consulta, o custo assintótico do algoritmo decide se a correção acontece em tempo real ou se trava o sistema.

O objetivo deste trabalho é comparar três estratégias para o mesmo problema e provar o custo de pior caso de cada uma, confirmando as provas com medições:

  1. Recursão ingênua (divisão e conquista sem memoização);
  2. Wagner-Fischer [2] (programação dinâmica bottom-up), incluindo a otimização de espaço para duas linhas;
  3. Ukkonen [3] (programação dinâmica restrita a uma faixa diagonal de largura 2k+12k+1, com corte por limiar).

2. Definição formal do problema

Sejam a=a1a2⋯ama = a_1 a_2 \cdots a_m e b=b1b2⋯bnb = b_1 b_2 \cdots b_n duas cadeias sobre um alfabeto Σ\Sigma. Uma operação de edição é uma inserção, uma deleção ou uma substituição de um caractere, cada uma com custo 1. A distância lev(a,b)\mathrm{lev}(a,b) é o menor número de operações que transforma aa em bb.

Seja D[i][j]=lev(a1⋯ai,b1⋯bj)D[i][j] = \mathrm{lev}(a_1\cdots a_i,\; b_1\cdots b_j). Então:

D[i][0]=i,D[0][j]=j, D[i][0] = i, \qquad D[0][j] = j,

D[i][j]=min{D[i−1][j]+1(deleção de ai)D[i][j−1]+1(inserção de bj)D[i−1][j−1]+[ai≠bj](substituição ou 𝑚𝑎𝑡𝑐h) D[i][j] = \min\begin{cases} D[i-1][j] + 1 & \text{(deleção de } a_i\text{)}\\ D[i][j-1] + 1 & \text{(inserção de } b_j\text{)}\\ D[i-1][j-1] + [a_i \neq b_j] & \text{(substituição ou } \textit{match}\text{)} \end{cases}

onde [ai≠bj][a_i \ne b_j] vale 1 se os caracteres diferem e 0 caso contrário. A resposta é D[m][n]D[m][n].

Justificativa da recorrência (subestrutura ótima). Considere um alinhamento ótimo entre a1⋯aia_1\cdots a_i e b1⋯bjb_1\cdots b_j e olhe para sua última coluna. Ela tem exatamente uma de três formas: aia_i alinhado com nada (deleção), nada alinhado com bjb_j (inserção), ou aia_i alinhado com bjb_j (substituição ou match). Removendo essa coluna, o que sobra é um alinhamento ótimo do subproblema correspondente; se não fosse, trocá-lo por um melhor reduziria o custo total, o que contradiz a otimalidade. Logo D[i][j]D[i][j] é o mínimo das três opções.

Exemplo: lev(𝚔𝚒𝚝𝚝𝚎𝚗,𝚜𝚒𝚝𝚝𝚒𝚗𝚐)=3\mathrm{lev}(\texttt{kitten}, \texttt{sitting}) = 3 (k→s, e→i, inserir g).

2.1 Modelo de custo

Adotamos o modelo RAM: comparação de caracteres, soma e mínimo de inteiros custam O(1)O(1). A operação elementar contada é:

  • na recursão ingênua, uma chamada da função lev(i,j)\mathrm{lev}(i,j);
  • nos algoritmos de programação dinâmica, o cálculo de uma célula D[i][j]D[i][j] com i,j≥1i,j \ge 1.

Cada uma executa um número constante de instruções, então o tempo total é proporcional à contagem. O pior caso T(m,n)T(m,n) é o maior número de operações elementares sobre todas as entradas de tamanhos mm e nn. Usamos nn para o caso m=nm = n.

3. Abordagem 1: Recursão ingênua

LEV(a, b, i, j):
    se i = 0: retorne j
    se j = 0: retorne i
    c ← 0 se a[i] = b[j], senão 1
    retorne min( LEV(a, b, i-1, j) + 1,
                 LEV(a, b, i, j-1) + 1,
                 LEV(a, b, i-1, j-1) + c )

Toda chamada com i,j≥1i, j \ge 1 gera sempre três chamadas, independentemente do conteúdo das cadeias. Portanto o número de chamadas depende só de (m,n)(m,n): o pior caso, o melhor caso e o caso médio coincidem, e qualquer entrada serve para medir o pior caso. Contando a própria chamada:

T(i,0)=T(0,j)=1,T(m,n)=1+T(m−1,n)+T(m,n−1)+T(m−1,n−1). T(i,0) = T(0,j) = 1, \qquad T(m,n) = 1 + T(m-1,n) + T(m,n-1) + T(m-1,n-1).

Teorema 1 (limite superior). T(m,n)≤3m+nT(m,n) \le 3^{m+n} para todo m,n≥0m,n \ge 0. Logo T(n,n)=O(9n)T(n,n) = O(9^n).

Prova (indução em m+nm+n). Base: T(i,0)=1≤3iT(i,0) = 1 \le 3^{i} e T(0,j)=1≤3jT(0,j) = 1 \le 3^{j}. Passo: sejam m,n≥1m,n \ge 1 (logo m+n≥2m+n \ge 2) e suponha a hipótese válida para somas menores. Então

T(m,n)≤1+3m+n−1+3m+n−1+3m+n−2=1+793m+n≤3m+n, T(m,n) \le 1 + 3^{m+n-1} + 3^{m+n-1} + 3^{m+n-2} = 1 + \tfrac{7}{9}\,3^{m+n} \le 3^{m+n},

pois a última desigualdade equivale a 3m+n≥9/23^{m+n} \ge 9/2, verdadeiro para m+n≥2m+n \ge 2. ◼\blacksquare

Teorema 2 (limite inferior). T(m,n)≥(m+nm)T(m,n) \ge \binom{m+n}{m}. Em particular, T(n,n)≥4n2n+1=Ω(4n/n)T(n,n) \ge \dfrac{4^n}{2n+1} = \Omega(4^n/n).

Prova. Defina L(m,n)=(m+nm)L(m,n) = \binom{m+n}{m}. Temos L(i,0)=L(0,j)=1L(i,0) = L(0,j) = 1 e, pela regra de Pascal, L(m,n)=L(m−1,n)+L(m,n−1)L(m,n) = L(m-1,n) + L(m,n-1). Descartando termos não negativos da recorrência de TT, obtemos T(m,n)≥T(m−1,n)+T(m,n−1)T(m,n) \ge T(m-1,n) + T(m,n-1), com as mesmas bases. Por indução em m+nm+n, T(m,n)≥L(m,n)T(m,n) \ge L(m,n). Para m=nm = n: (2nn)\binom{2n}{n} é o maior dos 2n+12n+1 termos de ∑t=02n(2nt)=4n\sum_{t=0}^{2n}\binom{2n}{t} = 4^n, logo (2nn)≥4n/(2n+1)\binom{2n}{n} \ge 4^n/(2n+1). ◼\blacksquare

Conclusão. Ω(4n/n)≤T(n,n)≤O(9n)\Omega(4^n/n) \le T(n,n) \le O(9^n): o algoritmo é exponencial no pior caso (e em todos os casos).

Observação (valor exato). Fazendo U=T+12U = T + \tfrac12, a recorrência vira U(m,n)=U(m−1,n)+U(m,n−1)+U(m−1,n−1)U(m,n) = U(m-1,n) + U(m,n-1) + U(m-1,n-1) com U=32U = \tfrac32 nas bordas. Essa é a recorrência dos números de Delannoy 𝒟(m,n)\mathcal D(m,n) [6], logo

T(m,n)=3𝒟(m,n)−12,𝒟(n,n)=Θ((3+22)nn), T(m,n) = \frac{3\,\mathcal D(m,n) - 1}{2}, \qquad \mathcal D(n,n) = \Theta\!\left(\frac{(3+2\sqrt2)^n}{\sqrt n}\right),

e portanto T(n,n)=Θ((1+2)2n/n)≈Θ(5,83n/n)T(n,n) = \Theta\big((1+\sqrt2)^{2n}/\sqrt n\big) \approx \Theta(5{,}83^n/\sqrt n). Verificação: 𝒟(2,2)=13\mathcal D(2,2) = 13 dá T(2,2)=19T(2,2) = 19 e 𝒟(3,3)=63\mathcal D(3,3) = 63 dá T(3,3)=94T(3,3) = 94, valores que coincidem com a contagem medida (Tabela 1).

Nota. O limite O(3min(m,n))O(3^{\min(m,n)}), às vezes citado para este algoritmo, não é um limite superior válido: 3n3^n é na verdade um limite inferior (basta seguir a diagonal). A Tabela 1 mostra T(13,13)≈2,1⋅109T(13,13) \approx 2{,}1\cdot10^9, enquanto 313≈1,6⋅1063^{13} \approx 1{,}6\cdot10^6.

Espaço. A profundidade máxima da pilha é m+nm+n (cada chamada reduz i+ji+j em pelo menos 1), logo o espaço é O(m+n)O(m+n).

4. Abordagem 2: Wagner-Fischer (programação dinâmica)

A recursão recalcula os mesmos subproblemas inúmeras vezes, mas só existem (m+1)(n+1)(m+1)(n+1) subproblemas distintos. Wagner e Fischer [2] preenchem a tabela DD de baixo para cima, linha a linha. Quando D[i][j]D[i][j] é calculado, as três dependências já estão prontas.

WAGNER-FISCHER(a, b):
    para i ← 0 até m: D[i][0] ← i
    para j ← 0 até n: D[0][j] ← j
    para i ← 1 até m:
        para j ← 1 até n:
            c ← 0 se a[i] = b[j], senão 1
            D[i][j] ← min(D[i-1][j] + 1, D[i][j-1] + 1, D[i-1][j-1] + c)
    retorne D[m][n]

Correção. Por indução na ordem de preenchimento (linha a linha, da esquerda para a direita): ao calcular D[i][j]D[i][j], as células (i−1,j)(i-1,j), (i,j−1)(i,j-1) e (i−1,j−1)(i-1,j-1) vêm antes nessa ordem e já contêm os valores corretos. A atribuição aplica exatamente a recorrência da Seção 2.

Teorema 3 (tempo). O algoritmo executa Θ(m⋅n)\Theta(m\cdot n) operações para qualquer entrada; o pior caso é Θ(m⋅n)\Theta(m\cdot n), ou Θ(n2)\Theta(n^2) quando m=nm=n.

Prova. Sejam c1,c2,c3c_1, c_2, c_3 as constantes de custo do corpo do laço interno, de uma iteração de inicialização e do trecho fixo. Então

T(m,n)=c3+c2(m+n+1)+∑i=1m∑j=1nc1=c1mn+c2(m+n+1)+c3. T(m,n) = c_3 + c_2\,(m+n+1) + \sum_{i=1}^{m}\sum_{j=1}^{n} c_1 = c_1\,mn + c_2\,(m+n+1) + c_3.

Para m,n≥1m,n \ge 1, vale m+n+1≤3mnm+n+1 \le 3mn, logo c1mn≤T(m,n)≤(c1+3c2+c3)mnc_1\,mn \le T(m,n) \le (c_1 + 3c_2 + c_3)\,mn, isto é, T=Θ(mn)T = \Theta(mn). O número de iterações não depende dos caracteres, então todas as entradas de tamanho (m,n)(m,n) custam o mesmo. ◼\blacksquare

Teorema 4 (espaço). A tabela completa ocupa (m+1)(n+1)=Θ(mn)(m+1)(n+1) = \Theta(mn) células. Mantendo apenas a linha anterior e a atual, e escolhendo como colunas a cadeia mais curta, o espaço cai para 2(min(m,n)+1)=Θ(min(m,n))2(\min(m,n)+1) = \Theta(\min(m,n)), sem alterar o tempo.

Prova. O cálculo da linha ii lê apenas a linha i−1i-1 (dependências de cima e da diagonal) e a própria linha ii (dependência da esquerda). Depois que a linha ii está completa, nenhuma linha anterior a ii volta a ser lida e pode ser descartada. Como lev(a,b)=lev(b,a)\mathrm{lev}(a,b) = \mathrm{lev}(b,a), podemos trocar as cadeias para que o comprimento das linhas seja min(m,n)\min(m,n). ◼\blacksquare

O custo dessa otimização é perder a tabela usada no backtracking, que reconstrói o alinhamento. Para obter o alinhamento em espaço linear existe o algoritmo de Hirschberg [4]. A Tabela 3 mostra o impacto prático: para m=n=105m = n = 10^5 com inteiros de 4 bytes, a tabela completa precisaria de cerca de 37 GB, enquanto as duas linhas ocupam 781 KB.

5. Abordagem 3: Ukkonen (faixa diagonal com limiar kk)

Num corretor ortográfico só interessam palavras próximas: queremos saber se lev(a,b)≤k\mathrm{lev}(a,b) \le k para um limiar pequeno (tipicamente k≤3k \le 3). Ukkonen [3] observou que, nesse caso, só uma faixa diagonal da tabela precisa ser calculada.

UKKONEN(a, b, k):                         ▷ supõe m ≥ n (troca se preciso)
    se m − n > k: retorne "> k"           ▷ corte em O(1)
    INF ← k + 1
    para i ← 1 até m:
        para j ← max(1, i−k) até min(n, i+k):
            V[i][j] ← min(V[i−1][j] + 1, V[i][j−1] + 1,
                          V[i−1][j−1] + [a_i ≠ b_j], INF)
        se min_j V[i][j] > k: retorne "> k"   ▷ corte antecipado
    retorne V[m][n] se V[m][n] ≤ k, senão "> k"

Células fora da faixa |i−j|≤k|i-j| \le k valem INF =k+1= k+1. Na implementação, apenas duas linhas são mantidas, como na Seção 4.

Lema 1. D[i][j]≥|i−j|D[i][j] \ge |i - j|.

Prova. Cada operação de edição altera o comprimento da cadeia em no máximo 1. Para transformar uma cadeia de comprimento ii numa de comprimento jj são necessárias pelo menos |i−j||i-j| operações. ◼\blacksquare

Lema 2 (valores truncados). Para toda célula da faixa, V[i][j]=min(D[i][j],k+1)V[i][j] = \min(D[i][j],\,k+1).

Prova (indução na ordem de preenchimento). Pelo Lema 1, toda célula fora da faixa tem D>kD > k, e portanto $(D, k+1) = k+1 = $ INF, que é exatamente o valor que o algoritmo lhe atribui. Para uma célula da faixa, suponha que as três vizinhas valem min(D*,k+1)\min(D_\ast, k+1). Como somar uma constante não negativa e tomar mínimos comuta com o truncamento em k+1k+1, temos min(min(x,k+1)+w,…,k+1)=min(min(x+w,…),k+1)\min(\min(x,k{+}1)+w,\;\ldots,\;k{+}1) = \min(\min(x+w,\ldots),\;k{+}1). Logo V[i][j]=min(D[i][j],k+1)V[i][j] = \min(D[i][j], k+1). ◼\blacksquare

Lema 3 (corte antecipado). Se, para alguma linha ii, minjV[i][j]>k\min_j V[i][j] > k, então D[m][n]>kD[m][n] > k.

Prova. Suponha, por contradição, que d=D[m][n]≤kd = D[m][n] \le k. O backtracking a partir de (m,n)(m,n) define um caminho ótimo até (0,0)(0,0) em que os valores de DD não diminuem no sentido de (0,0)(0,0) para (m,n)(m,n), pois cada passo soma um custo 0 ou 1. Esse caminho atravessa a linha ii em alguma célula (i,j)(i,j) com D[i][j]≤d≤kD[i][j] \le d \le k. Pelo Lema 1, |i−j|≤k|i-j| \le k, então a célula está na faixa e, pelo Lema 2, V[i][j]=D[i][j]≤kV[i][j] = D[i][j] \le k. Isso contradiz a hipótese. ◼\blacksquare

Teorema 5 (correção). O algoritmo devolve lev(a,b)\mathrm{lev}(a,b) se este valor é ≤k\le k, e “> k” caso contrário. Prova: o corte por comprimento é correto pelo Lema 1 aplicado a (m,n)(m,n); o corte antecipado pelo Lema 3; e o valor final pelo Lema 2. ◼\blacksquare

Teorema 6 (pior caso). Com n=min(m,n)n = \min(m,n) e k≥1k \ge 1, o algoritmo executa O(k⋅n)O(k\cdot n) operações. Esse limite é atingido: para a=ba = b com |a|=n≥k|a| = n \ge k, o número exato de células calculadas é

T=(2k+1)n−k(k+1), T = (2k+1)\,n - k(k+1),

que é ≥(k+1)n\ge (k+1)\,n para n>kn > k. Portanto o pior caso é Θ(k⋅min(m,n))\Theta(k \cdot \min(m,n)).

Prova. (Limite superior.) Se m−n>km - n > k, o algoritmo termina em O(1)O(1). Caso contrário m≤n+km \le n + k, e cada linha calcula no máximo min(n,2k+1)\min(n,\,2k+1) células. Assim T≤m⋅min(n,2k+1)T \le m \cdot \min(n, 2k+1). Se k≤nk \le n, temos T≤(n+k)(2k+1)≤2n⋅3k=6knT \le (n+k)(2k+1) \le 2n \cdot 3k = 6kn. Se k>nk > n, temos T≤(n+k)n<2knT \le (n+k)\,n < 2kn. Em ambos os casos, T=O(k⋅n)T = O(k\cdot n).

(O limite é atingido.) Se a=ba = b, então D[i][i]=0D[i][i] = 0 em toda a diagonal. O mínimo de cada linha é 0 e o corte antecipado nunca ocorre, então toda a faixa é calculada. As células internas fora da faixa satisfazem |i−j|>k|i-j| > k. Do lado j>ij > i há ∑d=k+1n−1(n−d)=(n−k)(n−k−1)2\sum_{d=k+1}^{n-1}(n-d) = \tfrac{(n-k)(n-k-1)}{2} delas, e o mesmo número do outro lado. Logo

T=n2−(n−k)(n−k−1)=(2k+1)n−k(k+1). T = n^2 - (n-k)(n-k-1) = (2k+1)\,n - k(k+1).

Por fim, T−(k+1)n=k(n−k−1)≥0T - (k+1)n = k(n-k-1) \ge 0 para n>kn > k, ou seja, T=Ω(k⋅n)T = \Omega(k\cdot n). ◼\blacksquare

Melhor caso. Se |m−n|>k|m - n| > k, a resposta sai em O(1)O(1) sem calcular nenhuma célula: Ω(1)\Omega(1). Com entradas aleatórias, o corte antecipado também costuma ocorrer nas primeiras linhas. Nas medições da Tabela 2, cadeias aleatórias com k=5k = 5 calcularam entre 51 e 84 células, independentemente de nn.

Espaço. Com duas linhas, Θ(min(m,n))\Theta(\min(m,n)), como no Teorema 4.

6. Validação empírica

Todos os algoritmos foram implementados em TypeScript (arquivo src/lib/levenshtein.ts) com um contador de operações elementares. A correção foi verificada por testes automáticos (npm run check):

  • 5 000 pares aleatórios, nos quais as quatro implementações (recursiva, matriz completa, duas linhas e Ukkonen com k=0..12k = 0..12) concordam;

  • Wagner-Fischer. A razão ops/n2\text{ops}/n^2 é exatamente 1 e o tempo quadruplica quando nn dobra: comportamento quadrático.

  • Curvas planas. Uma razão ops/limite\text{ops}/\text{limite} que fica constante quando nn cresce é a evidência empírica de que o limite de pior caso provado é apertado.

Lição de implementação. Uma primeira versão do Ukkonen reiniciava a linha inteira (fill) a cada iteração. O contador de células continuava linear, mas o tempo crescia de forma quadrática, porque o fill custa O(n)O(n) por linha. A versão final reinicia apenas a célula de borda da faixa. Isso mostra que a operação elementar escolhida na análise precisa de fato dominar o custo real.

Para kk fixo e n→∞n \to \infty, a hierarquia é Θ(kn)≪Θ(n2)≪Θ(5,83n/n)\Theta(k\,n) \ll \Theta(n^2) \ll \Theta(5{,}83^n/\sqrt n). Num corretor ortográfico que compara a palavra digitada com NN palavras do dicionário, o custo total passa de N⋅Θ(n2)N\cdot\Theta(n^2) para N⋅O(kn)N\cdot O(k\,n). Na prática é ainda menor, porque a maioria das palavras do dicionário é descartada pelo corte de comprimento ou pelo corte antecipado.

8. Aplicação interativa (Levenshtein Lab)

Como demonstração prática, foi desenvolvida uma aplicação web em Next.js 15, React 19, TypeScript e Tailwind CSS 4, com tema escuro e layout em tela dividida: controles à esquerda e visualização à direita. Os algoritmos ficam numa biblioteca pura (src/lib/levenshtein.ts), sem dependência de React, que é compartilhada pela interface e pelos testes.

Decisões de engenharia.

  • O benchmark roda num Web Worker: mesmo quando a recursão leva segundos, a interface continua responsiva. O Módulo B tem também um botão que executa a recursão na thread principal, para mostrar o travamento real.
  • Acima de um orçamento de chamadas, a recursão é abortada e a curva continua com a contagem exata prevista pela recorrência (calculada em O(mn)O(mn)), sem executar bilhões de chamadas.
  • A aplicação é exportada como site estático, sem servidor.

9. Conclusão

Provamos formalmente o custo de pior caso das três abordagens e confirmamos cada limite com contagens exatas de operações:

  • a recursão ingênua é exponencial em todas as entradas, crescendo cerca de 5,83×5{,}83\times por letra;
  • Wagner-Fischer elimina a recomputação e atinge Θ(mn)\Theta(mn), com espaço reduzível a Θ(min(m,n))\Theta(\min(m,n));
  • Ukkonen explora o limiar kk e atinge Θ(k⋅min(m,n))\Theta(k\cdot\min(m,n)) no pior caso e Ω(1)\Omega(1) no melhor, o que o torna adequado para correção ortográfica em tempo real.

O trabalho também mostra que a análise assintótica precisa estar alinhada com a implementação: um detalhe como reiniciar uma linha inteira pode, sem alterar a contagem de células, transformar um algoritmo linear em quadrático.
